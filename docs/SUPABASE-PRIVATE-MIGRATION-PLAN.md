# แผนย้ายข้อมูลส่วนตัวไป Supabase Free

เอกสารนี้เป็นแผนเทคนิค ไม่ใช่คำแนะนำทางกฎหมายหรือภาษี และยังไม่ใช่การยืนยันว่าจะส่งข้อมูลจริง

## ข้อสรุป

- ให้ Supabase เป็นฐานข้อมูลหลักของข้อมูลทีมงาน เงินเดือน บัญชีธนาคาร เลขภาษี สัญญา และไฟล์ส่วนตัว
- ให้ Firebase Auth ทำหน้าที่เข้าสู่ระบบต่อไปในระยะแรก แล้วให้ API ฝั่งเซิร์ฟเวอร์ตรวจสอบ Firebase ID token ก่อนเรียก Supabase
- หากเปิด direct Supabase Auth ในอนาคต ให้กำหนดสิทธิ์ผู้ดูแลผ่าน `app_metadata.role` ที่เขียนโดยเซิร์ฟเวอร์เท่านั้น ห้ามอ่าน role จาก `user_metadata` หรือข้อมูลที่ผู้ใช้ส่งมาเอง
- Firestore ไม่ควรเก็บข้อมูลส่วนตัวซ้ำอีกชุด หากไม่จำเป็น
- งาน sync รายวันใน `scripts/sync-firestore-daily.cjs` ส่งเพียงเอกสารสรุปต่อวัน เช่น ชั่วโมงรวมและยอดรวมตามทีม ไม่มีชื่อ UID เลขบัญชี เลขภาษี ลิงก์ไฟล์ หรือเอกสาร
- โหมดเริ่มต้นเป็น dry-run; ต้องระบุ `--commit` จึงเขียนเอกสารสรุปหนึ่งฉบับต่อวัน

## ความเข้าใจเรื่อง “อ่าน/เขียนวันละ 2 ครั้ง”

Firestore นับการอ่าน/เขียนเป็นรายเอกสาร ไม่ใช่จำนวน HTTP request หากส่ง batch 500 เอกสารใน request เดียว จะยังนับการเขียนตามจำนวนเอกสาร ดังนั้นระบบนี้ลดการใช้ Firestore โดยไม่ส่งข้อมูลส่วนตัวและเขียนเพียง aggregate รายวันหนึ่งเอกสาร แต่ไม่สามารถรับประกันว่าอ่าน/เขียนเป็น 2 ครั้งรวมทั้งระบบได้

## สิ่งที่สร้างไว้ใน repository

- `supabase/private-workforce-schema.sql`: ตารางส่วนตัว, การเข้ารหัสค่าเลขบัญชี/เลขภาษีฝั่งแอป, RLS, private storage bucket และ append-only audit/history
- `scripts/sync-firestore-daily.cjs`: อ่านเฉพาะคอลัมน์ที่ใช้ทำสรุปจาก Supabase, ตรวจชื่อฟิลด์เสี่ยง PII, dry-run และเขียน Firestore เมื่อใช้ `--commit`
- `.github/workflows/sync-firestore-daily.yml`: เรียกวันละครั้งเวลา 01:00 น. เวลาไทย และรองรับการกดทำงานเอง

## ขั้นตอนเปิดใช้งานที่ต้องตรวจโดย Dev/ผู้ดูแล

1. ตรวจ SQL กับทนาย/ผู้เชี่ยวชาญ PDPA และผู้ดูแลระบบก่อน apply
2. ตั้งค่า secrets ใน GitHub Actions: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `FIREBASE_PROJECT_ID`, `GOOGLE_SERVICE_ACCOUNT_JSON`
3. ให้ service account มีสิทธิ์เฉพาะเขียนเอกสาร `dailyTeamSummaries/*` เท่าที่จำเป็น ไม่ให้สิทธิ์อ่านหรือจัดการทั้งโปรเจกต์
4. ทดลอง `node scripts/sync-firestore-daily.cjs` แบบ dry-run และตรวจ payload ว่า `containsPII: false`
5. เปิด `--commit` หลังผ่านการทดสอบ แล้วค่อยเปลี่ยนหน้าโปรไฟล์/สัญญา/เงินเดือนให้เรียก API Supabase
6. ห้ามลบข้อมูลเดิมจาก Firebase จนกว่าจะตรวจสอบยอด, สิทธิ์, signed URL, retention และแผน rollback ครบ

## การส่งข้อมูลสำคัญจริง

ไฟล์บัตรประชาชน สมุดบัญชี เลขภาษี และสลิปยังไม่ได้ย้ายในรอบนี้ ไม่มีการอ่านหรือส่งข้อมูลจริงจาก Firebase ไป Supabase การย้ายจริงต้องระบุชุดข้อมูล, วัตถุประสงค์, ผู้มีสิทธิ์เข้าถึง, ระยะเวลาเก็บ และยืนยันอีกครั้งก่อนเริ่มโอน
